# Репетитор CRM — Telegram Mini App

Мини-приложение для репетитора: ученики, расписание занятий, учёт оплат,
напоминания ученикам от бота и материалы к уроку (теория и домашка в PDF),
которые собирает ИИ.

Репозиторий — два приложения: фронт (React + Vite, этот каталог) и бэкенд
в [api/](api/) (NestJS + PostgreSQL + Prisma, бот на grammY в том же процессе).
Всё про API, схему данных, бота и статистику — в [api/README.md](api/README.md).

Стадия — пилот: оплаты и тарифов нет, материалы и распознавание расписания
ограничены пробными лимитами.

## Запуск локально

Нужен локальный Postgres и настроенный `api/.env` (см. `api/README.md`).
Два терминала:

```bash
npm run dev:api   # бэкенд на http://localhost:3001/api
npm run dev       # фронт на http://localhost:5173
```

Открыть http://localhost:5173 в обычном браузере — вход из Telegram не нужен.
Dev-сервер подписывает initData тестового репетитора токеном бота из `api/.env`
(`tools/vite-dev-telegram-login.js`), и бэкенд проверяет его как настоящий.
Изменения в коде подхватываются сразу, без перезагрузки страницы.

- Фронт в dev-режиме ходит в локальный API — адрес в `.env.development`.
- Тестовый пользователь по умолчанию — `Dev` с id `100000001`. Другого можно
  задать в `.env.development.local` (`DEV_TG_USER_ID`, `DEV_TG_FIRST_NAME`,
  `DEV_TG_USERNAME`).
- В `api/.env` для такой работы стоит `BOT_MODE="off"`: локальный бот с тем же
  токеном не отбирает обновления у продового и никому не пишет. Чтобы
  проверить бота, переключите на `polling`.
- Dev-вход отвечает только запросам с этого компьютера и в сборку не попадает.

## Сборка

```bash
npm run build     # результат в dist/
npm run preview   # локальная проверка собранной версии
```

`base: './'` в `vite.config.js` даёт относительные пути, поэтому сборка
одинаково работает и в корне домена, и в подпапке (GitHub Pages).

## Деплой

**Фронт — Cloudflare** ([wrangler.jsonc](wrangler.jsonc)): после `npm run build`
каталог `dist/` выкладывается как статика. Адрес API задаётся при сборке
переменной `VITE_API_URL` (см. [.env.example](.env.example)).

**Бэкенд** — отдельно, см. [api/README.md](api/README.md). Миграции применяются
на старте (`npm run start:prod`).

Хостинг фронта обязательно по HTTPS — Telegram не откроет Mini App по HTTP.

## Подключение к боту

1. В [@BotFather](https://t.me/BotFather) → `/newapp`, выбрать своего бота.
2. Указать название, описание, картинку 640×360.
3. В поле Web App URL вставить адрес задеплоенного приложения.
4. BotFather выдаст ссылку вида `t.me/<bot>/<app>` — по ней открывается Mini App.

Ссылки, которые раздаются репетиторам, стоит помечать источником:
`t.me/<bot>?start=src_<метка>` или `t.me/<bot>/<app>?startapp=src_<метка>`.
Метка попадёт в сводку `/stats` — см. «Статистика пилота» в [api/README.md](api/README.md).

## Устройство проекта (Feature-Sliced Design)

```
src/
├── app/        инициализация, состояние, навигация
├── pages/      экраны: today, calendar, students, money, student, lesson
├── widgets/    составные блоки: month-summary, student-list
├── features/   действия пользователя: onboarding, add-student, edit-student,
│               add-lesson, edit-lesson, import-schedule, lesson-material,
│               invite-student, notify-settings, send-feedback и другие
├── entities/   бизнес-сущности: student, lesson (модель + карточка)
└── shared/     переиспользуемое: lib, ui, api
```

Импорты идут строго вниз по слоям: `app → pages → widgets → features →
entities → shared`. Внутри слоя слайсы не импортируют друг друга напрямую —
общее выносится в `shared` или `entities`. Каждый слайс отдаёт публичный API
через свой `index.js`.

### Данные и вход

Данные живут на бэкенде. При открытии приложение отправляет `initData` из
Telegram на `POST /auth/login`, получает JWT и дальше ходит с ним
(`shared/api/client.js`). Состояние держит `app/model/useStore.js`: обновления
оптимистичные — экран меняется сразу, запрос уходит в фоне, при ошибке
изменение откатывается и показывается тост.

### Про Telegram SDK

Скрипт `telegram-web-app.js` подключается всегда, поэтому объект
`window.Telegram.WebApp` существует и в обычном браузере. Реальный запуск
из Telegram определяется по `initData` / `platform` (см. `shared/api/telegram.js`).
Вне Telegram `tg === null`, методы SDK не вызываются, а вместо невидимой
`MainButton` рендерится обычная кнопка «Сохранить».

Тема берётся из `themeParams` и подставляется в CSS-переменные, так что
приложение следует светлой/тёмной теме пользователя.

### Приглашение ученика и напоминания

**Telegram не даёт Mini App доступ к списку чатов** и **бот не может написать
первым** — это ограничения платформы. Поэтому порядок такой:

1. Репетитор создаёт карточку ученика и нажимает «Пригласить». API выпускает
   одноразовую ссылку `https://t.me/<bot>?start=<code>` с готовым текстом.
2. Текст уходит ученику через системный пикер чатов (`switchInlineQuery`),
   вне Telegram — копируется в буфер.
3. Ученик открывает ссылку и нажимает «Начать» — бот привязывает его аккаунт
   к карточке, статус становится «Подключён».
4. С этого момента планировщик на бэкенде шлёт ученику напоминания о занятиях
   по настройкам из его карточки.
