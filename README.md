# Репетитор CRM — Telegram Mini App

Мини-приложение для репетитора: ученики, расписание занятий и учёт оплат.
Данные хранятся в `localStorage` браузера — бэкенда нет (это следующий этап).

## Запуск локально

Нужен локальный Postgres и настроенный `api/.env` (см. `api/README.md`).
Два терминала:

```bash
npm run dev:api   # бэкенд на http://localhost:3001/api
npm run dev       # фронт на http://localhost:5173
```

Открыть http://localhost:5173 в обычном браузере — вход из Telegram не нужен.
Dev-сервер подписывает initData тестового репетитора токеном бота из `api/.env`
(`tools/vite-dev-telegram-login.js`), и бэкенд проверяет его как настоящий.
Изменения в коде подхватываются сразу, без перезагрузки страницы.

- Фронт в dev-режиме ходит в локальный API — адрес в `.env.development`.
- Тестовый пользователь по умолчанию — `Dev` с id `100000001`. Другого можно
  задать в `.env.development.local` (`DEV_TG_USER_ID`, `DEV_TG_FIRST_NAME`,
  `DEV_TG_USERNAME`).
- В `api/.env` для такой работы стоит `BOT_MODE="off"`: локальный бот с тем же
  токеном не отбирает обновления у продового и никому не пишет. Чтобы
  проверить бота, переключите на `polling`.
- Dev-вход отвечает только запросам с этого компьютера и в сборку не попадает.

## Сборка

```bash
npm run build     # результат в dist/
npm run preview   # локальная проверка собранной версии
```

`base: './'` в `vite.config.js` даёт относительные пути, поэтому сборка
одинаково работает и в корне домена, и в подпапке (GitHub Pages).

## Деплой

**Netlify / Vercel** — подключить репозиторий, команда сборки `npm run build`,
каталог публикации `dist`.

**GitHub Pages** — собрать и выложить содержимое `dist/`
(например, через ветку `gh-pages` или GitHub Actions).

Хостинг обязательно должен быть по HTTPS — Telegram не откроет Mini App по HTTP.

## Подключение к боту

1. В [@BotFather](https://t.me/BotFather) → `/newapp`, выбрать своего бота.
2. Указать название, описание, картинку 640×360.
3. В поле Web App URL вставить адрес задеплоенного приложения.
4. BotFather выдаст ссылку вида `t.me/<bot>/<app>` — по ней открывается Mini App.

## Устройство проекта (Feature-Sliced Design)

```
src/
├── app/        инициализация, состояние, навигация
├── pages/      экраны: today, calendar, students, money, student, lesson
├── widgets/    составные блоки: month-summary, student-list
├── features/   действия пользователя: add-student, add-lesson,
│               edit-lesson-status, import-from-telegram, contact-student,
│               invite-student, notify-settings
├── entities/   бизнес-сущности: student, lesson (модель + карточка)
└── shared/     переиспользуемое: lib, ui, api, config
```

Импорты идут строго вниз по слоям: `app → pages → widgets → features →
entities → shared`. Внутри слоя слайсы не импортируют друг друга напрямую —
общее выносится в `shared` или `entities`. Каждый слайс отдаёт публичный API
через свой `index.js`.

### Про Telegram SDK

Скрипт `telegram-web-app.js` подключается всегда, поэтому объект
`window.Telegram.WebApp` существует и в обычном браузере. Реальный запуск
из Telegram определяется по `initData` / `platform` (см. `shared/api/telegram.js`).
Вне Telegram `tg === null`, методы SDK не вызываются, а вместо невидимой
`MainButton` рендерится обычная кнопка «Сохранить».

Тема берётся из `themeParams` и подставляется в CSS-переменные, так что
приложение следует светлой/тёмной теме пользователя.

### Выбор учеников из Telegram

**Telegram не даёт Mini App доступ к списку чатов** — такого метода нет ни в
WebApp SDK, ни в Bot API, это ограничение приватности. Поэтому экран «Выбрать
из Telegram» сейчас работает на демонстрационном списке
(`features/import-from-telegram/model/chats.js`).

Чтобы подключить реальных учеников на втором этапе:

1. Ученик пишет боту `/start`.
2. Бэкенд сохраняет его `chat_id`, имя и username.
3. В `chats.js` меняется тело `fetchChats()` на запрос к своему API —
   остальной код экрана трогать не нужно.

### Связь с учеником

В карточке ученика есть три действия: открыть чат (`openTelegramLink` по
username), отправить расписание и напомнить про оплату (готовый текст уходит
в нативный пикер чатов через `switchInlineQuery`, вне Telegram — копируется
в буфер).

### Приглашение и уведомления

**Бот не может написать первым** — Telegram это запрещает. Поэтому ученик
сначала должен сам открыть бота и нажать «Начать».

1. В карточке ученика — «Пригласить в бота». Создаётся код и ссылка вида
   `https://t.me/<bot>?start=<code>`, текст уходит в чат ученика.
2. Статус меняется на «Приглашение отправлено».
3. Ученик открывает ссылку и нажимает «Начать». Бот получает
   `/start <code>` и по коду понимает, какому ученику он соответствует.
4. Статус — «Подключён», боту разрешено слать напоминания.

Пока бэкенда нет, четвёртый шаг отмечается вручную кнопкой
«Ученик уже подтвердил». С ботом статус будет приходить с сервера.

Имя бота задаётся при сборке:

```bash
VITE_BOT_USERNAME=my_tutor_bot npm run build
```

Без этой переменной в ссылке останется заглушка `your_tutor_bot`,
о чём приложение честно предупреждает.

**Настройки уведомлений** у каждого ученика свои: за сколько часов напомнить,
повторное напоминание перед занятием, напоминание о долге и часы тишины.
Приложение их только хранит — применять будет бот.

### Что нужно от бэкенда

| Шаг | Что делает |
|---|---|
| `/start <code>` | сохранить `chat_id` ученика по коду приглашения |
| `GET /students` | отдать статусы подключения в приложение |
| `POST /lessons` | принять занятия, чтобы планировщик их видел |
| Планировщик | раз в 5 минут искать занятия и слать `sendMessage` |

Планировщик учитывает `notify` каждого ученика: `beforeHours`,
`beforeMinutes`, `debtReminder` и окно тишины `quietFrom`/`quietTo`.

## Хранилище

Ключ `tutor-crm:v3`. Данные из старых версий (`tutor-crm:v2`, `tutor-crm-v1`)
мигрируют автоматически при первом запуске, недостающие поля дозаполняются
значениями по умолчанию.

## Чего пока нет

Бэкенда, реального списка чатов, отправки сообщений от имени бота,
авто-напоминаний, графиков, групповых занятий — всё это следующий этап.
